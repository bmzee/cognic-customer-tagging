## Benchmarks in CI

Run with `.github/workflows/benchmark.yml` on a GitHub-hosted `ubuntu-latest` runner (run 39065474356, phase 4 at `4bb80df`), on seeded synthetic data from `tools/bench.py`:

| Measurement | Result |
| --- | --- |
| Generate 200,000 customers and 5,000,000 transactions | done (synthetic) |
| Rebuild of the profile store, 200,000 customers / 5,000,000 transactions (5,000,001 events) | 1,595.7 s; 770,951 tags held; store 6,271,881,216 bytes |
| Continuous updates on that store, one event per transaction (3,000 events) | 8.6 events/s; p50 110.18 ms; p99 242.49 ms |
| The same events in batches of 500 | 340.5 events/s |
| A daily tick (re-evaluates all 200,000 customers) | 447.3 s |
| Rebuild of 20,000 customers / 500,000 transactions | 151.8 s; store 626,487,296 bytes |
| Long property run, incremental equals batch (200 short and 20 long seeds) | 9 tests OK in 743.3 s |

Rebuild time grows about linearly with the data (10 times the transactions: 10.5 times the time). The one-event rate falls as the store grows, so a change feed should be read in batches; making single events cheap at this size is left open (Q27).
