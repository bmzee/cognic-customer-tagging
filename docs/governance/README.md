# Governance templates

> **To be completed by the bank's compliance team.** These are generic, jurisdiction-neutral templates. They record what the plugin already does and leave every decision that belongs to the bank blank. They are not legal advice: what applies is set by the bank's regulator and data-protection law.

| Template | What it covers |
| --- | --- |
| [dpia.md](dpia.md) | A DPIA-style assessment: purpose, data, necessity and proportionality, risks and mitigations, residual risk and sign-off |
| [customer-rights.md](customer-rights.md) | Explaining a tag to a customer, objection and opt-out (the flag the builder honours), access and correction |
| [retention.md](retention.md) | How long each kind of record is kept, and what the bank must decide |
| [audit-trail.md](audit-trail.md) | What the store records about every run, and how to reproduce one |
| [taxonomy-change-control.md](taxonomy-change-control.md) | How a rule changes: version, hash, changelog, reviewer, tag cards, fairness and drift |

Fields marked _[bank]_ are for the bank to fill in. Everything else describes the plugin as built; if a statement here stops being true, the template must change with the code.
